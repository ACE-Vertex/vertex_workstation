# Vertex Workstation — FORGE Real APPLY / ROLLBACK Human Gate 000022

## Why APPLY did not light

This was not a color-state bug.

The current `ArtifactInspector.tsx` literally rendered APPLY as:

- `disabled`
- `APPLY / FORGE · NEXT PASS`

and ROLLBACK was also hard-disabled.

So STAGE could become VERIFIED/GREEN correctly while APPLY could never arm.

## 000022

This pass implements the next missing FORGE mutation lane.

Flow:

`READY -> STAGE -> STAGED -> HUMAN APPLY -> APPLIED -> ROLLBACK`

APPLY is armed only when the currently selected artifact has a real in-memory
`ForgeStageResult` from the current session.

Green historical color alone does not arm APPLY.

## Rust-owned APPLY

The frontend does not copy files.

`forge_apply_stage` in Tauri/Rust:

1. validates the stage id
2. reopens the immutable `stage_report.json`
3. requires `STAGE_LOCK` with `authority=HUMAN_APPLY`
4. rechecks authorized production root
5. rehashes `artifact.vra`
6. rehashes every staged payload
7. blocks path traversal and symlink targets
8. checks target existence has not drifted since Stage
9. backs up every existing target before target mutation
10. writes target files from immutable staged payload
11. verifies final target SHA256
12. writes `apply_report.json` and `APPLY_LOCK`

If a multi-file APPLY fails after mutation begins, Rust attempts automatic
restore of the already-entered operations before returning the error.

## Rust-owned ROLLBACK

ROLLBACK arms only after a successful APPLY.

Before restoring, it verifies that every current target still matches the exact
SHA256 written by that APPLY. If a human or another process changed a target
after APPLY, rollback is blocked rather than overwriting the newer edit.

Existing files are restored from the stage-specific backup root.
Files that did not exist before APPLY are removed.

## Runtime acceptance

1. Start the immutable build generated by verification.
2. Select a READY artifact.
3. Click STAGE.
4. Confirm STAGED and green history state.
5. APPLY / FORGE must now be enabled/green.
6. Click APPLY / FORGE.
7. Visible processing must show APPLYING.
8. Ledger must show APPLY PASS, mutation count, backup root.
9. ROLLBACK must become enabled/red.
10. Confirm target file contents actually changed.
11. Click ROLLBACK on a disposable test artifact.
12. Confirm previous target bytes are restored / newly-created files removed.

Do not call APPLY Runtime GREEN until the real target mutation is observed.
